# 게임 기획서 v0.1 — ProjectSlash (임시 프로젝트명)

> 작성일: 2026-11-06  
> 문서 목적: AI(Claude)를 활용한 **1인 개발용 핵심 액션 프로토타입** 제작 명세  
> 1차 목표: **PC 웹 브라우저에서 플레이 가능한 2D 프로토타입**  
> 권장 개발 방식: **Godot 4.7 안정 버전 + GDScript + Compatibility 렌더러 → HTML5/Web 내보내기**  
> 2차 방향: 같은 Godot 프로젝트의 Android/iOS 네이티브 확장 가능성 검토

## 문서 읽는 법

- **[확정]**: 기획자가 명시적으로 정한 규칙. 임의 변경하지 않는다.
- **[MVP 제안]**: 프로토타입을 실행 가능하게 만들기 위한 임시 설계. 플레이 테스트 후 변경 가능.
- **[튜닝]**: 구체적인 값은 초기 임시값으로 설정하고 에디터에서 조정할 수 있게 만든다.
- **[추후 결정]**: 아직 명확히 정해지지 않았으므로 구현 전에 변경하기 쉽도록 분리하거나 최소 동작만 구현한다.

이 문서의 목표는 게임의 재미를 검증하는 것이다. 화려한 비주얼보다 **와이어 → 스윙·도약 → 돌진 베기 → 다음 와이어**의 손맛과 플레이 가능성을 우선한다.

## 1. 게임 개요

### 1.1 한 줄 소개

오른쪽으로 자동 전진하며 공중에서 떨어지지 않도록 **건물에는 와이어를 걸고, 적에게는 고속 돌진해 베어내는** 2D 횡스크롤 생존 액션 게임.

### 1.2 레퍼런스와 역할

- **플래피 버드 / 쿠키런**: 전진을 멈추지 않고 장애물 패턴을 돌파하며 기록을 갱신하는 반복 플레이.
- **산나비**: 줄에 매달려 관성을 이용하는 와이어 액션의 감각.
- **벽력일섬 연출**: 짧고 빠른 돌진으로 적을 관통해 베는 액션의 속도감.

레퍼런스의 캐릭터·아트·애니메이션·사운드를 그대로 복제하지 않는다. 게임 규칙과 액션 경험만 참고한다.

### 1.3 핵심 재미(Pillars)

1. **끊기지 않는 전진**: 캐릭터는 자동 전진하며, 고도 유지 실패 시 추락한다.
2. **서로 다른 역할의 두 액션**: 건물은 와이어, 적은 돌진으로 돌파한다.
3. **연속 액션의 리듬**: 와이어에서 얻은 궤적을 돌진으로 이어가고 다음 와이어로 재연결한다.
4. **타이밍의 숙련**: 연결 위치와 해제 타이밍, 돌진 타이밍을 잘 선택할수록 안정적이고 빠른 이동이 가능하다.

### 1.4 게임 목표

- **[확정]** 가능한 한 멀리 이동한다.
- **[확정]** 이동 거리가 기본 점수이며 일정 시간 내 와이어·돌진을 연속 성공하면 콤보 보너스를 얻는다.
- **[확정]** 추락하거나 즉사형 위험 장애물에 충돌하면 게임 오버한다.
- **[확정]** 일반 건물/장애물 접촉은 즉사하지 않고 이동 속도를 감소시킨다.

## 2. 최초 제작 범위(MVP v0.1)

### 2.1 구현 필수

- 캐릭터 오른쪽 자동 전진, 중력, 공중 이동 및 속도 제한
- 마우스 조준 기반 **건물 와이어 연결/해제**
- **보정형 자동 스윙**: 방향키 없이 전방 장애물을 넘도록 스윙을 보조
- 와이어 해제 시 관성 유지 및 조건부 상향 도약
- **범위 내 전방 적 자동 타기팅** 및 고속 돌진 베기
- 와이어 사용 중 유효한 적에게 돌진할 때 와이어 해제 후 돌진 전환
- 건물, 적, 치명적 위험 구역의 기본 충돌·상호작용
- 추락/위험 구역 게임 오버 및 즉시 재시작
- 단일 **수동 배치 테스트 코스**(건물-건물-적-적-건물 등)
- 디버그 표시와 이동·스윙·돌진 튜닝 파라미터

### 2.2 의도적으로 제외

- 미려한 캐릭터 스프라이트, 애니메이션, VFX, 사운드, 세계관
- 적의 자율 공격 및 복잡한 AI
- 대규모 무한 맵 생성/패턴 편집 도구
- 상점, 스킨, 성장, 업적, 광고, 온라인 기능
- 모바일 터치 UI / 모바일 해상도 최적화
- 최종 점수 밸런싱 및 콤보 이펙트

**진행 원칙:** v0.1은 임시 사각형·원·선으로 구현하되, 물리 및 조작이 재미있는지 검증한다. 패턴 조합, 점수/콤보 완성은 v0.2 이후에 진행한다.

## 3. 화면/좌표/카메라

- **[확정]** 2D 측면 시점, 진행 방향은 **왼쪽 → 오른쪽(+X)**.
- **[확정]** 캐릭터는 기본적으로 공중에 체공하며 별도의 일반 점프 버튼은 없다.
- **[확정]** 카메라는 플레이어 진행을 추적한다.
- **[MVP 제안]** 카메라는 X축 중심으로 추적하고, Y축은 완만하게 보정하되 아래로 무한 추적하지 않는다.
- **[필수 주의]** 카메라가 낙하하는 플레이어를 끝없이 따라가면 '화면 아래로 추락하면 사망'이 성립하지 않는다. **코스 기준 하단 사망 높이(FallLimitY)** 또는 이에 준하는 독립된 판정선을 둔다.
- **[MVP 제안]** 진로를 보이도록 플레이어를 화면 중앙보다 약간 왼쪽에 배치한다.
- **[추후 결정]** 기준 해상도, 종횡비, 카메라 Y축 제한 폭, 화면 흔들림.

## 4. 입력과 조작

| 입력 | 동작 | 상태 |
|---|---|---|
| 마우스 이동 | 와이어 발사 방향 조준 | [확정] |
| 마우스 좌클릭 누름 | 조준한 건물의 유효 표면에 와이어 연결 시도 | [확정] |
| 마우스 좌클릭 유지 | 연결을 유지하고 자동 보정 스윙 진행 | [확정/MVP 해석] |
| 마우스 좌클릭 해제 | 와이어 해제, 조건 충족 시 상향 도약 | [확정] |
| 마우스 우클릭 | 사거리 안 전방 적에게 자동 돌진 베기 | [확정] |
| ESC | 일시정지 | [MVP 제안] |
| R 또는 UI 버튼 | 게임 오버 후 재시작 | [MVP 제안] |
| 방향키 | v0.1에서 사용하지 않음 | [확정: 우선 비교 실험용] |

- **[확정]** 방향키 없는 조작으로 우선 개발한다. 이후 좌우 방향키로 공중 속도를 미세 조정하는 B안을 별도 A/B 테스트한다.
- 조작 단순성을 해치지 않도록 조준은 **와이어에만** 필요하고 돌진은 **자동 타기팅**한다.
- **[MVP 제안]** 좌클릭 눌림 순간 1회 연결을 시도한다. 실패한 상태에서 버튼을 계속 누른다고 자동 재발사하지 않는다.
- **[MVP 제안]** 타기팅 대상이 없는 우클릭은 돌진하지 않는다. 와이어를 잡고 있었다면 그대로 유지한다. 이 동작은 테스트 후 변경 가능하다.

## 5. 플레이어 이동 및 물리

### 5.1 기본 이동

- **[확정]** 별도 입력이 없어도 캐릭터는 오른쪽으로 자동 전진한다.
- **[확정]** 중력으로 지속해서 아래로 하강한다.
- **[확정]** 일반 체공 이동에는 최고 속도 제한을 적용한다.
- **[확정]** 돌진은 체공 최고 속도보다 빠른 **별도 액션 속도**를 사용할 수 있다.
- **[튜닝]** 기본 전진 속도, 중력 가속도, 공중 가속도, 최고 수평/전체 속도, 감속 강도.

### 5.2 속도 설계

이동은 최소한 다음 속도를 구분한다.

1. **기본 체공 속도(AutoForwardSpeed)**: 방향 입력 없이 유지/접근하는 전진 속도.
2. **체공 최고 속도(MaxAirSpeed)**: 와이어 해제·돌진 종료 뒤 일반 체공 상태의 상한.
3. **돌진 속도(DashSpeed)**: 돌진 연출 중 사용되는 높은 고정/목표 속도.
4. **돌진 종료 후 속도 정책(PostDashVelocityPolicy)**: 즉시 상한 적용 vs 일정 시간에 걸친 감속.

- **[확정]** 돌진 이후에는 일반 체공 최고 속도를 넘는 속도가 영구 유지되지 않는다.
- **[추후 결정/튜닝]** 돌진 종료 즉시 상한 적용과 짧은 시간의 점진 감속을 플레이 테스트로 비교한다.
- **[중요]** '최고 속도'가 수평 성분 기준인지 전체 속력 기준인지 설정으로 명시하고, 두 방식을 테스트할 수 있게 한다. 초안에서는 **일반 체공의 수평 속도 상한 + 과도한 전체 속력 방지 상한**을 권장한다.

## 6. 와이어 액션 — 핵심 설계

### 6.1 와이어의 역할

- **[확정]** 와이어는 적에게 걸 수 없고 **건물에만** 연결한다.
- **[확정]** 와이어의 기본 느낌은 연결점을 중심으로 궤적을 그리는 **스윙형**이다.
- **[확정]** 방향키 입력 없이 스윙 중 **장애물 위쪽으로 진행하도록 자동 보정**한다.
- **[확정]** 좌클릭 해제 시 현재 관성을 유지하면서 **위쪽으로 살짝 튀어오르는 도약**을 적용한다.
- **[확정]** 와이어 중 유효한 돌진을 실행하면 와이어를 해제하고 적에게 돌진한다.

### 6.2 연결 대상/지점

- **[확정]** 시각적으로는 건물 표면에 와이어를 거는 방식.
- **[MVP 제안]** 실제 충돌 표면 전체가 아니라 **상단부를 포함한 유효 와이어 영역(AttachableSurface)** 을 건물별로 둔다. 마우스가 그 영역을 가리킬 때만 연결된다.
- **[MVP 제안]** 연결점은 영역 안에서 **레이캐스트가 맞은 표면 좌표**를 사용한다. 특정 고정 앵커 점에 강제로 스냅하지 않는다.
- **[MVP 제안]** 스윙할 수 없는 낮은 연결 위치는 대상 영역에서 제외한다. 향후 유효 영역이 충분히 넓어지면 연결 지점 자동 보정을 시험한다.
- **[튜닝]** 최대 연결 거리, 연결 가능한 표면 구역, 연결 지점 허용 각도, 최소 유지 시간.

### 6.3 와이어 자동 보정 스윙(권장 구현 방식)

> **의도:** 완전 자동 성공이 아니라, 플레이어가 적절한 표면을 골라 연결하면 별도의 방향키 없이 전방 장애물을 넘어갈 수 있도록 필요한 이동 에너지를 보조한다. 연결/해제 타이밍의 숙련은 유지한다.

1. 연결 순간 현재 위치, 현재 속도, 연결점, 로프 길이, 건물의 지붕 높이를 저장한다.
2. 로프가 팽팽해질 때 원 궤도에 가까운 스윙을 만든다. 연결 순간 속도 중 로프 방향 성분은 적절히 제한하고, 접선 속도를 반영한다.
3. 전방 진행에 도움이 되는 **접선 방향 보조 가속(SwingAssist)** 또는 **제한적인 로프 길이 감소(ReelAssist)** 를 준다.
4. 현재 위치·속도·접선 방향을 고려하여 필요한 보정만 가한다. 단순히 '항상 오른쪽 위 힘'을 추가하지 않는다(로프 구속과 충돌하면 부자연스러움).
5. 와이어 연결 중에도 건물은 충돌체로 남고, 캐릭터가 건물을 관통해 넘어가서는 안 된다.
6. 건물 상단을 실제로 넘을 수 없는 경우에는 자동 성공·텔레포트를 만들지 않는다. 대신 **유효 연결 영역/패턴 배치**를 조정해 통과 가능한 상황을 제공한다.

**중요한 물리/레벨 디자인 제약:** 와이어를 건물 **낮은 왼쪽 벽면**에 걸면, 단순 원형 스윙으로는 캐릭터가 건물 충돌체를 관통하지 않고 오른쪽으로 넘어가기 어려울 수 있다. 특히 연결점보다 지붕이 높다면 회전 방향을 고르는 것만으로 해결되지 않는다. 프로토타입에서는 **지붕에 가까운 연결 가능 영역 + 스윙/로프 당김 보정 + 해제 도약**으로 해결하고, 불가능한 배치는 만들지 않는다.

### 6.4 해제 도약(Release Boost)

- **[확정]** 좌클릭을 해제하면 와이어가 끊기고 캐릭터가 몸을 말아 위로 튀어오르는 느낌의 상향 도약이 발생한다. 애니메이션은 나중에 추가한다.
- **[확정]** 해제 직전의 수평 이동 관성을 보존한다.
- **[MVP 제안]** 와이어가 실제로 팽팽해졌고 최소 유지 시간/스윙량 조건을 만족할 때만 도약 보너스를 준다.
- **[MVP 제안]** 연결 직후 즉시 해제를 반복하는 것만으로 무한 상승하지 않도록 조건과 상한을 둔다.
- **[튜닝]** ReleaseUpImpulse, MinAttachDuration, MinTautDuration, ReleaseBoostCooldownOrCondition, 속력 상한.
- **[MVP 제안]** 스윙 자체는 기본 장애물을 넘는 주 이동 수단이고, 해제 도약은 마지막 고도 확보·다음 액션 연결의 보너스 역할이다.

### 6.5 와이어 종료/예외

- 좌클릭 해제: 해제 후 일반 체공, 유효한 스윙이었다면 도약 보정.
- 유효한 우클릭 돌진: 와이어 해제 후 돌진 상태로 즉시 전환(**이 경우 도약 보너스는 중복 지급하지 않음**: MVP 제안).
- 플레이어 사망: 와이어 즉시 종료.
- 건물에 충돌: 건물 통과 불가, 일반 충돌 감속 규칙 적용.
- 연결점이 사라지거나 로프 길이 제약이 성립하지 않으면 와이어 안전 해제.
- **[MVP 제안]** 와이어 동시 2개 연결·연속 자동 재연결은 지원하지 않음.

### 6.6 구현 관련 메모(Godot)

- **[권장]** `CharacterBody2D` 기반으로 이동 속도, 로프 구속, 접선 보정, 충돌 해결을 코드에서 명시적으로 관리한다. 이는 기획 요구인 **물리 기반 감각 + 게임적인 자동 보정 + 돌진 상태 전환**을 하나의 제어 흐름으로 조정하기 쉽다.
- `PinJoint2D`/`RigidBody2D`를 사용해도 되지만, 연결·해제·돌진 시 예상 가능한 제어가 어렵다면 고집하지 않는다.
- 로프는 초기엔 `Line2D` 하나로 시각화한다. 매 물리 프레임 갱신한다.
- 위치를 강제로 변경할 때 건물 내부로 이동시키지 않는다. 실제 이동은 충돌 검사를 거친다.
- 물리는 `_physics_process(delta)`에서 처리하며, 프레임 독립적으로 동작하도록 한다.

## 7. 돌진 베기

### 7.1 기본 규칙

- **[확정]** 돌진 베기는 **적에게만** 사용할 수 있다. 건물은 베지 못한다.
- **[확정]** 적은 와이어 연결 불가.
- **[확정]** 마우스 조준 없이 우클릭하면 범위 내 적을 자동 선택한다.
- **[확정]** 돌진은 공격이자 이동 수단이며, 적을 관통해 전방으로 진행한다.
- **[MVP 제안]** 적의 뒤쪽 일정 거리에서 돌진 종료. 추후 '적 위치에서 종료'와 비교 가능.
- **[확정]** 적은 초기 프로토타입에서 공격하지 않아도 된다(정지형 표적).

### 7.2 타깃 우선순위

1. 살아 있는 적만 후보.
2. 플레이어의 **전방(+X)** 에 있는 적만 후보.
3. 돌진 가능 거리 안의 적만 후보.
4. 후보가 여러 개면 **전방에서 가장 가까운 적** 선택. 동률이면 실제 거리 등으로 결정.
5. 후보가 없으면 돌진을 실행하지 않음.
6. 돌진 중 다른 적을 자동으로 추가 타기팅하지 않음.

- **[MVP 제안]** 타깃 선택 시 시야 가림/건물 관통 경로를 확인한다. 건물을 가로지르는 돌진을 허용하지 않는다.
- **[튜닝]** DashRange, DashSpeed, DashDuration/MaxDashTime, DashEndOffset.

### 7.3 돌진 상태 처리

- 타깃 확보 → 와이어 연결 중이면 해제 → 목표까지 빠르게 이동 → 타격 시 적 처리 → 적 뒤쪽 도달 또는 제한시간/충돌 시 종료 → 일반 체공 복귀.
- 돌진 이동 중에는 일반 체공 속도 제한 대신 돌진 속도를 적용한다.
- 돌진 종료 후 즉시 감속하는 A안과 짧은 시간에 걸쳐 감속하는 B안을 비교할 수 있도록 **PostDashVelocityPolicy**로 나눈다.
- **[MVP 제안]** 돌진 중 재돌진, 다중 타기팅, 연속 무적 시간은 제외한다.
- **[MVP 제안]** 충돌 시 원치 않는 건물 관통이나 벽 안에 박힘이 발생하지 않게 이동량을 물리 충돌 검사로 제한한다.

### 7.4 적 처치

- **[MVP 제안]** 타깃에 도달하면 적을 즉시 제거하고 성공 이벤트를 발생시킨다.
- 적마다 HP/피격 애니메이션/AI는 v0.1에서 제외한다.

## 8. 오브젝트 및 충돌 규칙

| 타입 | 와이어 | 돌진 베기 | 접촉 결과 | 상태 |
|---|---|---|---|---|
| 건물(Building) | 유효 표면만 가능 | 불가능 | 일반 감속; 관통 불가 | [확정 + 연결 영역 제안] |
| 적(Enemy) | 불가능 | 가능 | 돌진 성공 시 처치 | [확정] |
| 위험 장애물(Hazard) | 불가능 | 불가능 | 즉시 게임 오버 | [확정: 유형만 추후] |
| 하단 사망 경계(FallLimit) | 불가능 | 불가능 | 낙하 시 게임 오버 | [확정] |

- **[MVP 제안]** 건물/일반 장애물에 몸이 닿으면 현재 속도에 감속을 적용하되, 충돌 처리 결과가 물리적으로 건물을 관통하지 않아야 한다.
- **[MVP 제안]** v0.1에서 적이 비돌진 상태로 플레이어에 닿는 경우 일반 장애물처럼 감속 처리한다. 이후 위험 적과 일반 적을 구분할 수 있다.
- **[MVP 제안]** 위험 장애물은 시각적으로 구분되는 단순 붉은 사각형 1종이면 충분하다.

## 9. 액션 상태 및 전환

### 9.1 권장 상태

- `AIRBORNE`: 일반 자동 전진 + 중력
- `GRAPPLING`: 와이어 연결 + 보정형 스윙
- `DASHING`: 적 자동 타기팅 후 고속 돌진
- `DEAD`: 물리 액션 중지, 게임 오버

### 9.2 전환 표

| 현재 | 입력/조건 | 결과 |
|---|---|---|
| AIRBORNE | 유효 건물에 좌클릭 | GRAPPLING |
| AIRBORNE | 유효 전방 적에 우클릭 | DASHING |
| GRAPPLING | 좌클릭 해제 | AIRBORNE + 유효한 경우 해제 도약 |
| GRAPPLING | 유효 전방 적에 우클릭 | 와이어 해제 후 DASHING |
| DASHING | 타깃 처치/종료 조건 | AIRBORNE + 종료 속도 적용 |
| AIRBORNE/GRAPPLING/DASHING | 추락·위험 장애물 | DEAD |
| DEAD | 재시작 | 초기 위치 및 속도, 점수, 코스 리셋 |

- **[MVP 제안]** DASHING 중 와이어 연결은 불가능하다.
- **[MVP 제안]** 유효 타깃이 없는 우클릭은 상태를 바꾸지 않는다.
- **[MVP 제안]** 전환 우선순위: 사망 판정 > 유효 돌진 > 와이어 해제/연결 > 일반 이동.

## 10. 레벨 디자인

### 10.1 핵심 배치

- **[확정]** `건물 → 건물 → 적 → 적 → 건물`처럼 와이어와 돌진이 번갈아 필요한 구성.
- **[확정]** 장기적으로 무한 스크롤이며 **사전 제작한 패턴을 조합**한다.
- **[MVP 제안]** v0.1에서는 무한 생성이 아닌 **수동 배치한 짧은 테스트 코스**를 만든다.

### 10.2 테스트 코스 사례

1. **튜토리얼 건물 A**: 지붕 근처 유효 표면에 와이어를 걸어 스윙으로 오른쪽으로 이동.
2. **높은 건물 B**: 연결점이 상대적으로 낮아 더 큰 상승 보정 또는 적절한 해제 도약이 필요한 상황.
3. **적 C**: 자동 돌진으로 공백 구간을 이동.
4. **적 D**: 빠르게 이어지는 두 번째 돌진 타이밍 확인(기본 체공 상태에서 재발동).
5. **건물 E**: 돌진 후 속도를 다루며 와이어로 재연결.
6. **위험 구간**: 선택적으로 위험 사각형 배치, 추락 판정 및 재시작 확인.

### 10.3 불가능한 코스 방지

- 와이어 연결점이 높이/거리상 도달 가능한가?
- **건물 지붕 높이와 연결점 높이 차** 때문에 충돌체를 관통하지 않고 통과할 수 있는가?
- 와이어 해제 후 다음 표적까지 생존 가능한 체공 시간/속도가 있는가?
- 돌진이 필요한 구간에 전방 사거리 내 적이 존재하는가?
- 최고 속도에서도 다음 장애물을 인지할 수 있는 시야 여유가 있는가?
- 가속/감속을 포함해 적어도 하나의 반복 가능한 통과 경로가 있는가?

**v0.2 이상:** `PatternData`에 최소/최대 권장 진입 속도, 필요한 고도, 예상 출구 속도, 목표 액션 순서 등의 메타데이터를 저장해 안전한 패턴만 이어붙인다. 단순 랜덤 나열은 피한다.

## 11. 점수 및 콤보(정식 설계, v0.1은 최소 구현 가능)

- **[확정]** 기본 점수는 오른쪽으로 이동한 **거리**에 비례한다.
- **[MVP 제안]** 뒤로 밀린 상황에서 점수를 반복 획득하지 않도록 `최대 도달 X 좌표`로 거리 점수를 계산한다.
- **[확정]** 와이어 및 돌진을 **일정 시간 내 연속 성공**하면 콤보로 점수를 추가한다.
- **[MVP 제안]** 콤보 판정은 의미 있는 액션 완료 이벤트(유효 스윙 후 해제, 적 돌진 처치)를 기준으로 한다. 좌클릭 연타로 콤보를 올릴 수 없게 한다.
- **[튜닝]** ComboWindow, ComboMultiplier, 거리 점수 비율, 콤보 초기화 조건.
- **[MVP 제안]** v0.1 UI는 거리/현재 상태/디버그 속도만 표시해도 무방하다. 전체 점수·콤보 표현은 v0.2로 미뤄도 된다.

## 12. 튜닝 파라미터(숫자는 의도적으로 미확정)

> Claude는 아래 항목을 `Resource`, 설정 파일 또는 Inspector 노출 변수로 관리한다. **최종 게임 수치처럼 하드코딩하지 않는다.** 초기 임시값은 안전하게 통과 가능한 수준으로 정하고 테스트 결과를 문서에 기록한다.

| 그룹 | 파라미터 |
|---|---|
| 기본 이동 | `AutoForwardSpeed`, `Gravity`, `MaxAirHorizontalSpeed`, `MaxAirTotalSpeed`, `AirAcceleration` |
| 와이어 발사 | `GrappleMaxRange`, `MinValidAttachHeight`, `RopeLengthPolicy`, `AllowedSurfaceAngle` |
| 자동 스윙 | `SwingAssistStrength`, `SwingTargetForwardBias`, `ReelAssistStrength`, `MaxReelRate`, `MaxSwingSpeed` |
| 해제 도약 | `ReleaseUpImpulse`, `MinAttachDuration`, `MinTautDuration`, `MaxReleaseVerticalSpeed` |
| 돌진 | `DashRange`, `DashSpeed`, `DashEndOffset`, `MaxDashDuration`, `PostDashDeceleration` |
| 충돌/카메라 | `CollisionSpeedPenalty`, `FallLimitY`, `CameraForwardOffset`, `CameraVerticalFollowLimit` |
| 점수 | `DistanceScoreScale`, `ComboWindow`, `ComboScoreScale` |

변수 이름은 설계 예시이며 실제 코드의 일관성을 위해 한 번 정한 후에는 문서와 구현을 함께 수정한다.

## 13. 필수 디버그와 검증

### 13.1 디버그 UI/시각화

- 플레이어 위치, 속도(X/Y), 전체 속력, 액션 상태
- 와이어 연결점, 로프 길이, 연결 가능 표면, 로프 팽팽 여부
- 와이어 보정 가속 방향/크기(디버그 모드)
- 돌진 타깃, 돌진 사거리 및 선택된 타깃 강조
- 하단 사망 판정선 및 플레이어/건물 충돌체
- 속도/중력/도약 등의 주요 파라미터 실시간 또는 Inspector 조정

### 13.2 반드시 통과할 테스트

1. 아무 조작이 없으면 오른쪽으로 이동하면서 결국 하강한다.
2. 와이어는 건물의 **유효 표면**에만 걸리고 적에는 걸리지 않는다.
3. 와이어를 유지하면 방향키 없이 **전방을 향한 자동 보정 스윙**이 일어난다.
4. 낮은/높은 연결 위치를 바꿔 테스트해도 건물 내부 관통이나 위치 순간이동이 발생하지 않는다.
5. 짧은 연결 후 연속 해제를 반복하는 것만으로 무한 상승할 수 없다.
6. 정상 스윙 해제 시 수평 관성을 유지하면서 상향 도약한다.
7. 유효 적이 여러 명이면 전방에서 가장 가까운 적을 자동 선택한다.
8. 범위 밖/후방 적에게는 돌진하지 않는다.
9. 와이어 중 유효 적에게 돌진하면 와이어가 풀리고 돌진이 시작된다.
10. 돌진은 건물을 관통하지 않고 적을 베어 전방에 도달한다.
11. 돌진 종료 후 최종 체공 속도 상한이 지켜진다(즉시/점진 감속 비교 가능).
12. 건물에 부딪히면 즉시 죽지 않고 감속한다.
13. 위험 장애물과 하단 사망 경계는 정확히 게임 오버를 발생시킨다.
14. 카메라가 아래로 계속 따라가 추락 사망이 무효화되지 않는다.
15. 테스트 코스에서 `와이어 → 스윙/도약 → 돌진 → 돌진 → 와이어` 흐름이 실제로 가능한지 직접 확인한다.
16. 게임 오버 후 재시작하면 물리 상태, 와이어, 돌진 타깃, 적, 위치가 초기화된다.

### 13.3 재미 검증 질문

- 캐릭터가 의도와 다른 방향으로 튀어나가는 빈도가 높지 않은가?
- 와이어 해제의 타이밍에 따라 궤적 차이가 체감되는가?
- 돌진이 단순한 적 제거가 아니라 다음 연결을 위한 유의미한 이동 수단인가?
- 속도가 빠를 때 건물/적을 눈으로 구분하고 대응할 수 있는가?
- 건물-적-건물 교차 패턴이 두 액션을 자연스럽게 모두 사용하게 만드는가?

- 자동 보정 스윙(접선 보정 및 필요시 제한된 로프 당김)
- 해제 도약, 충돌체 비관통, 디버그 튜닝

**완료 기준:** 두 높이의 건물을 스윙과 해제로 넘을 수 있다.

### Phase 3 — 돌진 베기

- 자동 타기팅, 고속 돌진, 적 처치, 후속 속도 정책, 와이어→돌진 전환

**완료 기준:** 와이어→적 돌진→다음 와이어 흐름이 끊기지 않는다.

### Phase 4 — 플레이 테스트/웹 빌드

- 단일 교차 패턴 테스트 코스 완성
- 물리 수치 튜닝, 각 Phase 회귀 테스트
- 브라우저에서 실제 웹 빌드 확인

**완료 기준:** PC 브라우저에서 반복 플레이와 즉시 재시작이 된다.

### 이후(v0.2+)

- 패턴 프리팹/데이터 기반 조합, 무한 스크롤
- 거리 점수 및 콤보 UI
- 여러 위험 장애물, 게임 밸런스, 시각/사운드 연출
- 공중 좌우 조작 A/B 테스트
- 모바일 터치 입력과 해상도/성능 최적화

## 15. Claude가 임의로 바꾸면 안 되는 규칙

1. 기본 진행 방향은 오른쪽이며 플레이어는 자동 전진한다.
2. 와이어는 **건물 전용**, 돌진 베기는 **적 전용**이다.
3. 적 돌진에는 수동 조준이 필요하지 않다.
4. 방향키는 v0.1에서 비활성화한다.
5. 와이어는 스윙형이며 **자동 보정은 보조**이지 충돌을 무시한 자동 성공이 아니다.
6. 와이어 해제는 관성 유지 + 조건부 상향 도약이다.
7. 와이어 중 유효 타깃에 돌진하면 로프를 풀고 돌진한다.
8. 돌진 속도와 일반 체공 최고 속도는 구별한다.
9. 일반 건물 충돌은 감속이며 사망 조건은 추락/위험 장애물이다.
10. MVP는 **단일 테스트 코스에서 플레이 감각 검증**이 우선이다.
11. 정해지지 않은 수치나 정책은 변경하기 쉽게 구현하고 결정 기록을 남긴다.
12. 작업 완료를 주장하기 전 실제 실행/검증 여부를 구분해 보고한다.

## 16. 열린 결정 사항 / 실험 목록

| 항목 | 우선 실험안 | 비교·결정 시점 |
|---|---|---|
| 공중 좌우 조작 | 없음(A안) | 와이어/돌진 MVP 이후 B안과 비교 |
| 와이어 유효 범위 | 건물 상단 중심 표면 영역 | 충분히 재미있으면 연결 표면 확장 |
| 와이어 자동 보정 | 접선 가속 + 필요한 경우 제한적 로프 당김 | 스윙 궤적/통과 가능성 테스트 후 조정 |
| 해제 도약 | 유효 스윙 후 상향 속도 보너스 | 연결 직후 악용 및 감각 테스트 |
| 돌진 종료 위치 | 적 뒤쪽 | 적 위치 정지안과 비교 가능 |
| 돌진 종료 감속 | 점진 감속 우선 시험 | 즉시 속도 상한 적용과 A/B 비교 |
| 유효 타깃 없는 우클릭 | 입력 무시(와이어 유지) | 조작 피드백 테스트 |
| 적과 몸 충돌 | 일반 감속 | 난이도 테스트 후 조정 |
| 콤보 보너스 | 유효 행동 완료 기준 | v0.2에서 확정 |
